# 0020: 工程3-2Aの最小縦切りを架空データで実装する

## 状況

工程3-1で本番用データとSchemaの配置基盤は整備しましたが、site以外の正式なitem Schemaと参照関係は未実装でした。地域、団体、公式案内先、公式性確認根拠を一度に検証しつつ、分野・カード・関連データまで変更範囲を広げない最小単位が必要です。

## 決定

工程3-2を次の2つに分割します。

- 工程3-2A: 地域・団体・公式案内先・公式性確認根拠
- 工程3-2B: 分野・案内カード・カードと案内先の関連

工程3-2Aで`regions`、`organizations`、`sources`、`evidence`のcore・locale Schemaを正式化し、架空の国から架空の都道府県への地域階層を検証します。団体の英語名称は独自英訳にせず`official-ja-fallback`を使用し、日本語のみの案内先と英語の`destination_language_note`の関係を検証します。

本番用に登録する架空データはすべて`draft`と未確認状態にします。`published`の条件は、完全に架空のテストデータで確認します。実在する団体、自治体、URL、災害情報は登録しません。

実在情報の詳細な掲載・更新・削除手順は、公開用データ生成と画面仕様を確定し、実際の表示を確認した後に整備します。工程3-2Bは別PRで実装します。

## 理由

- 地域階層から公式性確認根拠までを、小さく一貫した参照関係として検証できる
- 実在情報を使わずにSchemaと意味検証の責務分担を固定できる
- `official-ja-fallback`により、根拠のない独自英訳を公式英語名称として扱うことを防げる
- 下書きの本番用データと公開条件のテストデータを分けることで、未確認情報の公開誤認を防げる
- 工程3-2Bを分けることで、カード表示仕様の未確定事項を先行実装せずに済む

## 影響

8 Schemaが正式なitemを受け入れ、12データファイルが架空itemを持ちます。対象外の17 Schemaは`maxItems: 0`、25データファイルは`items: []`を維持します。

本番用架空データは公開対象ではありません。公開対象抽出、公開成果物生成、画面、デプロイには影響しません。
