# 0021: 工程3-2Bの案内カード最小縦切りを架空データで実装する

## 状況

工程3-2Aで地域、団体、公式案内先、公式性確認根拠までを正式化しました。利用者の目的からその案内先へ到達するために、分野、案内カード、カードと案内先の関連を、画面や公開生成へ先行して検証できる最小のデータ契約が必要です。

## 決定

工程3-2Bで`sections`、`cards`、`card-source-links`のcore・locale Schemaを正式化します。第一版で確定済みの5分野を登録し、分野名はサイト自身の分類として扱うため「架空」を付けません。

工程3-2Aの`src-example-prefecture-official-home`へつながる架空カード1件と、架空のカード関連1件を登録します。本番用データはすべて`draft`とし、実在情報は登録しません。公開条件は完全な架空テストデータで確認します。

`publication_status: published`のカードには、構造上公開可能な`role: primary`の関連を最低1件必要とします。主案内先の最大件数は固定せず、現在日時による表示期間判定は後続の公開用データ生成工程へ残します。

アイコン、色、カードレイアウト、文字数上限はデータ項目へ追加せず、架空データによる画面MVPの確認後に判断します。工程3-2B後は災害・出来事より先に、公開用データ生成MVPと画面MVPへ進みます。実在情報の掲載・更新・非公開化・削除手順も画面確認後に整備します。

## 理由

- 利用者の目的から工程3-2Aの公式案内先までを、小さく一貫した参照関係として検証できる
- 5分野を画面実装前に安定した分類IDと表示順として共有できる
- 本番用の下書きデータと公開条件のテストデータを分け、未確認情報の公開誤認を防げる
- 公開カードの主案内先条件を公開生成工程より前に固定できる
- 現在日時判定や表示仕様を先行実装せず、後続MVPの確認結果を反映できる

## 影響

工程3-2Aの8 Schemaに工程3-2Bの6 Schemaを加え、正式なitem Schemaは14件になります。実装済み配列データファイルは21件、空配列を維持するデータファイルは16件です。対象外の11 Schemaは`maxItems: 0`を維持します。

本番用データは公開対象ではありません。公開対象抽出、公開成果物生成、画面、災害・出来事、デプロイには影響しません。
