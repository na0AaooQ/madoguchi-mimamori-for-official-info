# 0012: 言語共通のcoreと日英localeを分離する

## 状況

URL、確認日、状態、参照関係と、表示名称・説明・ボタン文言を同じレコードへ混在させると、言語追加や改訂時に重複と不整合が生じやすくなります。

## 決定

言語に依存しない情報を`data/core/`、日本語・英語の表示文言を`data/locales/ja/`と`data/locales/en/`へ分離し、同じIDで結合します。

公開対象言語のlocaleが不足する場合は公開しません。日本語文の暗黙フォールバックは、公式名称として明示する`official-ja-fallback`を除いて行いません。

## 理由

- URLや確認状態を言語ごとに重複管理せずに済む
- 日英の欠落と改訂不一致を検証できる
- 内部情報と利用者向け文言の責務が明確になる
- 将来の言語追加でも共通データを再利用できる

## 検討した代替案

- 一つのJSONレコード内に全言語の文言を持たせる
- 言語ごとにURLや状態を含む完全なデータセットを複製する
- 英語文がない場合に日本語文を自動表示する

## 影響

coreとlocaleの同一ID、`locale_status`、改訂番号、日英存在条件を検証する必要があります。管理用coreをそのまま公開せず、言語別の公開成果物を生成します。
