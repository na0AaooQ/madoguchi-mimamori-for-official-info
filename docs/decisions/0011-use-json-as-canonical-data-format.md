# 0011: 管理データの正本にJSONを採用する

## 状況

団体、案内先、確認根拠、日英文面、関連データを、実行コードと分離して厳密に検証できる正本形式が必要です。

## 決定

管理データの正本にJSONを採用します。JavaScriptは将来の検証・変換・公開成果物生成に使用できますが、正本データにはしません。

## 理由

- 構造を明確に表現できる
- JSON Schemaで型、必須項目、列挙値を厳密に検証しやすい
- Codexや各種ツールで扱いやすい
- 実行可能なJavaScriptコードとデータの境界を保てる
- 公開用成果物の生成処理と相性がよい

## 検討した代替案

- YAML: 可読性に利点がある一方、インデント、型解釈、重複キーの運用リスクがある
- JavaScriptモジュール: 柔軟だが、データと実行コードの境界が曖昧になり、内部データの意図しない公開や処理の複雑化につながる

## 影響

JSON固有の厳格な構文を守り、JSON Schema Draft 2020-12と意味検証を実装する必要があります。具体的なJSONファイルとスキーマは後続工程で追加します。
