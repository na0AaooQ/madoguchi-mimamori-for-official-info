# ADR 0023: preview画面を静的HTMLとして生成する

## 状況

Git管理中の架空preview公開データから、低速通信、JavaScript無効環境、モバイルからPCまで利用できる日英画面を再現可能に作る必要があります。ブラウザで`navigation.json`を取得して主要表示を組み立てる方式は、JavaScript失敗時に案内情報を失い、公開データの変更と画面成果物のレビューも分離します。

## 決定

- ビルド時に日英の完成済み静的HTMLを生成し、Git管理する
- 公開案内情報は日英`navigation.json`だけを入力とし、管理用`data/`を直接参照しない
- 生成HTMLを直接編集せず、生成元から再生成する
- navigationにない画面固有文言を、厳格に検証する日英localeへ分離する
- JavaScriptなしでも主要情報と内部ナビゲーションを利用可能にする
- previewの外部URLは通常テキストとし、外部リンクを無効にする
- 補助JavaScriptは文字サイズ切替だけに使い、`sessionStorage`へ許可値だけを保存する
- AWS、production画面、実在情報、デプロイを対象外とする

### 採用しなかった案

- ブラウザで`navigation.json`をfetchする案: JavaScriptや通信失敗時に主要表示を失うため採用しない
- 生成HTMLをGit管理しない案: 入力と実際の画面差分を同じPRで確認できないため採用しない
- 管理用dataから直接画面を生成する案: 既存の公開境界と公開データ契約を迂回するため採用しない
- 画面固有文言をテンプレートへ散在させる案: 日英キー対応と不足を厳格に検証しにくいため採用しない

## 理由

完成済みHTMLなら、JavaScriptを無効にしても説明、分野、カード、団体、案内先を標準HTMLで利用できます。公開JSON、画面用locale、生成成果物を分離し、同じ入力からのバイト一致を検証することで、内部情報の混入、手編集、生成忘れ、古い分野ページを検出できます。
