# 0013: 災害と案内目的の出来事を分離する

## 状況

一つの災害には、水道、道路、住宅、医療、支援など複数の案内目的があります。これらを災害レコードへ直接詰め込むと、案内先の重複や、現在状況を蓄積するデータベースへの拡張を招きやすくなります。

## 決定

`disasters.json`で災害を識別し、`events.json`で各災害に属する案内目的を管理します。出来事はニュース記事、個別被害、個別事故ではなく、利用者が確認したい内容のまとまりとします。

災害・出来事には現在の被害、停電、断水、運行、診療、安全性などを保存しません。

## 理由

- 一つの災害に複数の案内目的を明示的に関連付けられる
- 案内先を目的別に整理しながら重複管理を避けられる
- 災害の識別と画面上の案内状態を区別できる
- 速報・現在状況のデータベース化を避けられる

## 検討した代替案

- 災害レコードへすべての案内目的と案内先を埋め込む
- ニュース記事や個別被害を出来事として保存する
- 通常カードだけで災害別案内も表現する

## 影響

出来事は必ず一つの災害へ属し、案内先との関係は`disaster-source-links.json`と`event-source-links.json`で分けて管理します。`site_guidance_status`は災害の終了ではなく、本サイト上の案内状態を表します。
