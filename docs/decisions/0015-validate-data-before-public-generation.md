# 0015: データを検証してから公開成果物を生成する

## 状況

JSON構文が正しくても、存在しないID参照、日英欠落、改訂不一致、期限矛盾、公式性根拠不足、内部項目の混入は検出できません。管理データをそのまま配信すると、内部情報も公開される危険があります。

## 決定

JSON Schema Draft 2020-12による構造検証と、独自処理によるファイル間の意味検証を分離して実施します。Errorが一つでもある場合は公開成果物の生成を停止します。

公開対象だけを抽出し、内部専用項目を除外して日英成果物を生成し、生成後にも内部項目の混入を再検証します。最後に人が公式性、安全性、日英表現、アクセシビリティを確認します。

## 理由

- 構造違反とファイル間の不整合をそれぞれ適切に検出できる
- 問題のあるデータを公開前に止められる
- 管理用の内部情報を公開成果物から分離できる
- 自動検証で扱えない意味・表現・操作性を人が補える

## 検討した代替案

- JSON構文だけを確認する
- JSON Schemaだけでファイル間の関係も扱う
- 警告を表示しつつ、Errorがあっても生成を続ける
- 管理データをそのままブラウザへ配信し、画面側で内部項目を隠す

## 影響

Error、Warning、Infoの区分、終了コード、検証順序、公開抽出、生成後再検証を実装する必要があります。機械検証の成功だけを公開承認とは扱いません。
