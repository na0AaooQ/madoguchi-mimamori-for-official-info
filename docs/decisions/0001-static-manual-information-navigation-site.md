# 0001: 静的・手動確認型の情報案内サイトとする

## 状況

災害時の公式情報は複数の機関に分散しています。一方、本サイトが自動収集や速報配信を行うと、古い情報の残存、誤認、運用負担の増大が生じます。

## 決定

静的HTML・CSS中心の案内サイトを想定します。JavaScriptへの依存を最小限にし、JavaScriptなしでも主要リンクを利用可能にします。AI、Web検索による自動取得、外部API、クローリング、スクレイピング、RSSを使用せず、人が公式性と案内先を確認します。

## 理由

- 公式情報そのものは発信団体が管理する方が安全である
- 自動取得の失敗や更新遅延による誤表示を避けられる
- 仕組みを単純にし、長期的に維持しやすくできる
- 速報性より安全性、誤認防止、維持可能性を優先できる

## 見送った案

- 災害情報を自動収集して集約する
- 外部APIやRSSから現在状況を表示する
- AIで情報を要約・分類・判定する
- JavaScriptを前提とした動的アプリケーションにする

## 安全・プライバシー・運用上の配慮

新サイト内に利用者向け入力フォームを設けず、センシティブ情報を収集・掲載しません。人による週次・月次確認と情報量上限により、確認可能な範囲を守ります。

## 将来の再検討条件

自動化を導入しても公式性、鮮度、障害時の挙動を検証でき、誤認防止と人的な監督を維持できる体制が整った場合に限り、個別の設計判断として再検討します。現時点では導入予定はありません。
