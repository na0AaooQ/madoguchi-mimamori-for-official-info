# 0016: 小さな縦切りから段階的に開発・検証する

## 状況

データ基盤、日英表示、公式性、安全性、アクセシビリティ、配信構成を同時に大規模実装すると、問題の原因と影響範囲を特定しにくくなります。

## 決定

確定設計、品質基盤、データ基盤、最小の縦切り画面、段階追加、ローカル画面確認、修正、同条件での再確認、回帰テストへの還元、公開前レビュー、ホスティング検討、検証環境、本番公開の順で進めます。

## 理由

- データから画面までの一経路を早期に確認できる
- 日英・リンク先言語・内部項目除外の問題を小さい範囲で見つけられる
- 画面で見つかった不具合を検証やテストへ還元できる
- ローカル、検証環境、本番の差を段階的に確認できる
- ホスティング方式を実装要件に基づいて判断できる

## 検討した代替案

- 全データと全ページを一度に実装する
- 画面確認を本番公開後まで行わない
- 自動テストだけで公開判断する
- AWS構成をデータ・画面要件より先に固定する

## 影響

各工程に目的、成果物、完了条件を設けます。画面確認で見つかった問題は修正後に同条件で再確認し、必要なテスト・Schema・意味検証・Linterへ還元します。
