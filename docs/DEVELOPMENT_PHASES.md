# 開発工程

## 文書の位置付け

この文書は、第一版を安全に実装・確認・公開するために作成した初期の工程1から工程13までの計画を記録する文書です。初期計画の目的、成果物、完了条件を残しつつ、2026年8月9日時点の実際の完了範囲と未実装範囲を注記します。

この文書は第一版開発時の工程計画・実績を残す歴史的文書です。今後の開発作業標準フローは `DEVELOPMENT_STANDARD_FLOW.md` を正本とし、標準フローの変更に合わせて本文書の過去の工程内容を更新・置換・削除しません。

## 現在状態

初回公開時は、初期計画にあった全5分野を公開条件とはせず、「公的機関・防災全般」と「ライフライン」の2分野、3カード、14案内先へ範囲を縮小して公開しました。その後BL-006-B、BL-006-C第一・第二・第三公開単位、BL-006-A第一公開単位を完了し、現在は5分野、8カード、24案内先を日本語・英語のproductionとして管理しています。GitHub Pages、カスタムドメイン、HTTPS、手動workflow、公開後確認まで完了しています。`npm run check`は629テストで成功しています。BL-009工程Bでは熊本productionを全国トップ・地域別URLへ移行し、公開反映は次回の手動workflowで行います。

BL-006-B「道路・交通」、BL-006-C「支援・復旧」の第一・第二・第三公開単位、BL-006-A「命・安全・医療」の第一公開単位は、PRレビュー・マージ・手動デプロイ・公開後確認まで完了しています。災害・出来事データを使う専用の期間限定案内、確認・更新履歴の利用者向け表示、staging、ダークモードなどは現在未実装です。未実装の機能・環境は[公開後バックログ](POST_LAUNCH_BACKLOG.md)で管理します。現在の実装・公開状況は[README](../README.md)と[公開後バックログ](POST_LAUNCH_BACKLOG.md)を正とします。

以下の「成果物」「完了条件」には初期計画を含みます。初期計画と異なる範囲で第一版を完了した箇所は、その旨を明記します。

## 全工程の原則

- 各工程の完了条件を満たしてから次へ進む
- 実装と同時に、該当する文書・検証・テストを更新する
- 自動検証と人による画面・内容確認を組み合わせる
- 現在状況の転載、内部情報の公開、日英の不整合を防ぐ
- 問題を修正した後は、同じ条件で再確認する
- 実際に見つかった不具合を再発防止の検証へ還元する

## 工程3: データ基盤の実装（現在は完了）

### 工程3-1: 共通Schema・空データ基盤（初期段階として完了）

確定した管理単位に対し、core 14、日本語13、英語13の40データファイルと、core 14・locale 13の27 Schemaを配置しました。3つの`site.json`だけを単一オブジェクトとし、その他37ファイルは空の`items`を持つ配列エンベロープです。

日本語と英語は同じlocale Schemaを利用します。この段階では未実装の25 Schemaを`maxItems: 0`で保護し、ファイル配置、JSON構文、Schema、`$id`、siteの最小整合性を`npm run validate:data`で検証しました。この「空データ」は工程3-1当時の状態であり、現在は正式なitem Schema、実在管理データ、意味検証、公開対象抽出、公開生成を実装済みです。

### 工程3-2: 架空データの最小縦切り（現在は完了）

予約用途ドメインと明確な架空名称を使用し、公式案内先と案内カードの最小縦切りを段階的に実装しました。正式なitem Schema、意味検証、公開生成、preview成果物を追加し、工程3-1の空データ保護を段階的に解除しました。

### 工程3の後続範囲（第一版に必要な範囲は完了）

ID・URL重複、公式性根拠、表示期間、公開可能件数、内部項目除外などの意味検証、公開対象抽出、公開成果物生成を段階実装しました。第一版の実在する団体と案内先は、人が公式性と更新手順を確認して管理データへ追加しています。災害別・期間限定案内のデータ基盤はありますが、現在の管理データは空で、production表示は未実装です。
