# 日英対応方針

## 文書の位置付け

この文書は、第一版の表示言語、公式名称、リンク先言語、日英文面の改訂・公開条件を定めます。第一版は未実装であり、英語版サイトの全利用者向け文面をこの文書で作成するものではありません。

## 第一版の対応言語

第一版から次の2言語へ正式対応します。

- 日本語（標準言語）
- 英語

その他の言語は将来対応とし、第一版では管理・公開対象に含めません。未対応言語が`display_locales`などへ指定された場合はErrorとします。

英語話者が熊本県・熊本市に関する公的機関・関係団体自身の公式情報へ到達しやすくすることが目的です。本サイトが外部の公式ページ本文を翻訳、転載、要約するものではありません。

## 言語共通データと表示文言

言語に依存しない情報は`data/core/`へ、日本語・英語の表示文言は`data/locales/ja/`と`data/locales/en/`へ分離します。詳細なファイル構成は[データモデル](DATA_MODEL.md)、確定フィールドは[データフィールド定義](DATA_FIELDS.md)を参照してください。

本サイト自身が作成する次の文言は、日本語・英語を管理します。

- サイト名、副題、説明
- 注意書き
- 分野名、カード名
- 案内目的
- ボタン文言
- 公開更新履歴
- その他の利用者向け説明

`core`と`locale`は同じ`id`で結合します。URL、確認日、状態、参照関係、対象地域などを言語ファイルへ重複させません。

## 団体の公式名称

団体自身が使用している公式英語名称を、公式ページなどの根拠から確認できる場合だけ、その名称を使用します。

公式英語名称を確認できない場合は、英語版でも日本語の正式名称をそのまま表示します。独自に翻訳した名称を公式英語名称として扱ってはいけません。名称とは別の説明文で、団体の役割を英語で案内することはできます。

言語別`organizations.json`の`name_kind`は次の3種類に限定します。

| 値 | 用途 |
| --- | --- |
| `official-ja` | 日本語の正式名称 |
| `official-en` | 根拠を確認できた公式英語名称 |
| `official-ja-fallback` | 公式英語名称を確認できないため英語版でも表示する日本語正式名称 |

`official-en`には、`evidence.json`で公式英語名称の根拠を関連付けます。`official-ja-fallback`の文字列は、対応する日本語正式名称と一致させます。

団体名称に`descriptive`を使用してはいけません。

## 災害名称

言語別`disasters.json`の`name_kind`は次の4種類です。

| 値 | 意味 |
| --- | --- |
| `official-ja` | 日本語の公式災害名称 |
| `official-en` | 公的機関が使用する公式英語名称 |
| `official-ja-fallback` | 公式英語名称を確認できないため英語版でも使用する日本語公式名称 |
| `descriptive` | 公式名称が確認できない災害を識別するための説明的名称 |

- 日本語localeの`official-ja`には、`target_type: disaster`、対象災害ID、`target_aspect: official-name`、`target_locale: ja`、`status: confirmed`の公開時点に有効な根拠を必要とする
- 英語localeの`official-en`には、`target_type: disaster`、対象災害ID、`target_aspect: official-name`、`target_locale: en`、`status: confirmed`の公開時点に有効な根拠を必要とする
- 英語localeの`official-ja-fallback`は、対応する日本語localeを`official-ja`とし、英語版の名称文字列を日本語公式名称と一致させ、同じ災害IDを対象とする`target_type: disaster`、`target_aspect: official-name`、`target_locale: ja`、`status: confirmed`の公開時点に有効な根拠を必要とする
- `descriptive`は、公式名称が確認できない災害名称に限定し、`official-name`の確認根拠を必須としない
- `descriptive`を団体の独自英訳を許可する目的に使用せず、本サイトによる公式認定を意味しない
- 現在の被害状況、安全性、規模、復旧状態などを説明的名称へ含めない

災害名称の根拠は、対象名称を実際に使用する公的機関・関係団体自身の公式ページなどで確認します。検索結果、第三者のSNS投稿、報道記事だけや、認証バッジ、フォロワー数、表示名だけを公式名称の根拠にしません。

## サイト表示言語とリンク先言語

サイトの表示言語と、外部の公式リンク先で利用できる言語を分けて管理します。

- `display_locales`: 本サイトのどの言語版に表示するか
- `destination_locales`: 外部の公式リンク先で利用できる言語

英語版から日本語だけの公式ページへ案内する場合は、リンク先が日本語であることを英語で明示します。外部ページが英語に対応していると推測したり、本サイト側で外部本文を翻訳したりしません。

## 言語別にURLが異なる場合

日本語ページと英語ページで公式URLが異なる場合は、別々の案内先レコードとして管理します。

- 例: `src-example-ja`
- 例: `src-example-en`
- 同一内容の言語違いを示す必要がある場合: `equivalent_source_group_id`

一つの案内先レコードで、表示言語に応じて未検証のURLへ動的に置き換える設計にはしません。

## localeレコードの状態と改訂

localeレコードは、少なくとも次を持ちます。

- `id`
- `locale_status`
- `content_revision`
- `content_reviewed_on`
- 英語では`based_on_ja_revision`

項目名は`locale_status`へ統一し、`translation_status`は使用しません。

`locale_status`の値は次のとおりです。

- `draft`
- `under-review`
- `published`
- `needs-update`
- `archived`

日本語の意味を変更した場合は、日本語の`content_revision`を増やします。英語は、翻訳時に基にした日本語の改訂番号を`based_on_ja_revision`へ記録します。

英語の`based_on_ja_revision`が日本語の`content_revision`と一致しない場合、英語データは公開できません。誤字修正などで改訂番号を増やすかどうかの詳細運用は後続工程で整備します。

## フォールバック方針

不足している英語文へ、日本語文を暗黙にフォールバック表示しません。文面が不足していることを自動的に隠したり、日本語と英語が混在した公開成果物を生成したりしません。

例外は、公式名称として明示的に`official-ja-fallback`を指定した場合だけです。この例外を一般の説明文、ボタン文言、注意文へ広げません。

## 日英の公開条件

公開中のcoreレコードをある言語で表示するには、少なくとも次を満たす必要があります。

- 対象言語が第一版の対応言語である
- 対応するlocaleレコードが存在する
- `locale_status`が`published`である
- 必須の利用者向け文言が揃っている
- 日本語・英語の改訂関係が整合する
- 公式名称の種別と根拠が整合する
- 日本語だけのリンク先を英語版へ表示する場合、リンク先言語の案内文がある

不足または不整合がある場合はErrorとし、そのレコードを含む公開成果物を生成しません。

## 人による確認

自動検証だけで翻訳品質や誤認防止を保証できません。公開前に人が次を確認します。

- 英語文が日本語の意味と一致する
- 独自訳を公式英語名称として扱っていない
- 公式英語名称の根拠が対象名称を実際に示している
- `official-ja-fallback`が日本語正式名称と一致する
- 災害の`official-ja`と`official-en`に対象災害と言語が一致する確認済み根拠がある
- 災害の`official-ja-fallback`に対応する日本語公式名称の確認済み根拠がある
- 団体名称に`descriptive`を使用していない
- 災害の`descriptive`名称に現在状況・安全性・規模を含めていない
- 日本語だけのリンク先であることが英語版に明示されている
- 「最新」「安全」「正しい」などを本サイトが保証する表現になっていない
- 外部の公式ページ本文を翻訳、転載、要約していない
- モバイル表示、読み上げ、キーボード操作で意味が伝わる

## URLパス

具体的なURLパス構成と、英語版を`/en/`へ配置するかは、この段階では決定しません。実装・ホスティング設計と合わせて後続工程で検討します。
