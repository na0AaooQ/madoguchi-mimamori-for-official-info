# 設計原則

## 目的と役割

> 災害時などに、熊本県内の状況を確認したい方や、地域外から支援したい方が、確認したい情報を担当する公的機関・関係団体を見つけ、その団体自身の公式発表へ速やかに到達できるよう支援する。

本サイトの役割は、公的機関・関係団体自身の公式情報への入口を案内することです。行政公式サイト、ニュースサイト、速報配信サービス、真偽判定サービス、団体の評価サービスにはなりません。

## 分かりやすさを情報量より優先する

リポジトリ内のproductionは5分野・8カード・24案内先です。GitHub PagesへのPR #31の反映と公開後確認は2026年8月9日に完了しています。将来拡張時は、公開画面上のまとまりを約17、管理する情報源を30件以内、常設・補助リンクを45件以内、同時に表示する期間限定リンクを8件以内とする運用上の目安を設けます。一つのカードの主な案内先は原則1〜3件です。

網羅性よりも、目的から迷わず公式情報へ進めることと、人が丁寧に維持できることを優先します。

## 速報・転載・真偽判定を行わない

- 現在の災害、避難、火災、停電、断水、運行、道路、診療などの状況を転載しない
- 最新見出しや公式ページ本文を転載・要約しない
- 非公式情報や目撃情報を掲載しない
- 情報の真偽を判定しない
- 団体や情報の信頼度を採点・ランキング化しない
- 現在の安全性を判定しない
- 避難、受診、移動などを自動判断しない
- AIによる要約や判断を行わない

変化の速い情報を転載すると、古い内容が残り、サイト側の記述が公式発表と誤認されるおそれがあります。利用者にはリンク先の公式情報を確認してもらいます。

## 人による確認を基本とする

Web検索、クローリング、スクレイピング、RSS、外部APIなどによる自動取得は行いません。公式サイトからのリンクなどを人が確認し、公式性の根拠、対象URL、公式性確認日を記録します。

災害・出来事データを使う専用の期間限定案内機能は未実装です。一方、個別Sourceとして期間限定の公式案内を人が有効性を確認したうえで掲載する場合があります。現在公開中の熊本県「令和8年熊本地震に係る義援金」はその例で、自動終了・自動判定は行いません。速報性より安全性、誤認防止、維持可能性を優先します。

## 完全無料・広告なし・ログイン不要

- すべての閲覧機能を無料で提供する
- 広告やアフィリエイトリンクを掲載しない
- 広告料、協賛、寄付によって掲載順や掲載可否を変えない
- ログインやアカウント登録を求めない
- 閲覧に個人情報入力を必要としない
- 新サイト内に利用者向け入力フォームを設けない

問い合わせのみ、任意で外部の[ポートフォリオサイトのお問い合わせページ](https://portfolio.na0aaooq.com/contact.html)を利用します。外部フォームにはポートフォリオサイト側のプライバシーポリシーが適用され、名前またはハンドルネーム、メールアドレス、問い合わせ本文などの入力が必要です。

## プライバシーと安全

利用者の個人情報を掲載情報として扱いません。行方不明者、安否不明者、被災者、負傷者、患者、救助対象者、搬送先などのセンシティブな情報を掲載しません。

現在はGitHub Pages、カスタムドメイン、HTTPSを使用します。productionではGoogle Analytics 4を利用し、Googleタグマネージャーは不使用、独自イベントは不使用、Googleシグナル、User-ID、広告関連機能は不使用です。GA4によりCookieを使用しますが、運営者独自のアクセス解析、広告目的のトラッキング、localStorageは使用しません。文字サイズ設定としてsessionStorageへ`standard`または`large`だけを保存し、previewにはGA4を出力しません。実際の実装と日本語・英語のプライバシー説明を一致させます。

## モバイル優先

- スマートフォンとタブレットを優先する
- 基本は1カラムとし、タブレット・PCでは必要に応じて2カラムとする
- 横スクロール前提の表を使用しない
- 大きなタップ領域を確保する
- カードの概要を閉じた状態に残し、詳細を開いて案内先情報とURLを確認できるようにする

## アクセシビリティ

- 色やアイコンだけで状態・意味を伝えない
- 適切な見出し階層を使い、各ページの`h1`は一つにする
- キーボード操作に対応する
- 本文へ移動するスキップリンクとページ内アンカーを設ける
- JavaScriptなしでも主要リンクと詳細を利用できるようにする
- productionの案内先、問い合わせ先、運営者プロフィールは新しいタブで開き、`target="_blank"`と`rel="noopener noreferrer"`を設定する
- previewの架空URLはリンク化せず、言語別の運営者プロフィールと問い合わせページだけを許可された実在外部リンクとする
- 外部サイトへ移動することを明示する
- PDFへのリンクはPDFであることを事前に表示する
- 「こちら」だけの曖昧なリンク文言を避ける
- ライト・ダーク双方を実装する場合は十分なコントラストを確保する
- 110番・119番を誤操作しやすい大きな発信ボタンや自動発信リンクにしない

## 情報を重複管理しない

同じ団体、URL、公式アカウント、相談先をページごとに別データとして管理しません。一つの情報源を複数の分野・カードから共通参照できる構造を目指します。

現在は、熊本市「救急安心センター事業（#7119）」日本語や熊本県公式の義援金案内を、各カードから案内する共通参照の実例として管理しています。将来別の導線から同じ情報源を参照する場合も重複登録しません。管理単位、具体的なJSONファイル、実装済みのJSON Schema、参照関係は[データモデル](DATA_MODEL.md)に従います。

## 技術方針

### 確定している方針

- 静的HTML・CSS中心を想定する
- JavaScriptへの依存を最小限にする
- JavaScriptなしでも主要リンクを利用可能にする
- AI、外部API、自動取得を使用しない
- 新サイト内に入力フォームを作らない
- 第一版から日本語・英語へ対応し、日本語を標準言語とする
- 管理データの正本にJSONを使用する
- 言語共通のcoreと日英localeを分離する
- JSON Schema検証とファイル間の意味検証を分離する
- Errorがある場合は公開成果物を生成しない
- 内部確認履歴と内部項目を公開成果物へ含めない

### 現在確定している実装構成

- GitHub Pages、カスタムドメイン、HTTPS、ルート`/`
- 日本語`/ja/`、英語`/en/`、ルート言語選択
- `workflow_dispatch`だけの手動デプロイ
- 文字サイズ切替だけにJavaScriptとsessionStorageを使用する
- Node.js、`node:test`、Ajv、ESLint、Prettier、独自検証を使用する

### 将来検討

- staging、自動デプロイ、稼働監視
- ライト・ダークモードを含む表示改善
- 対象地域や言語の拡大

将来検討事項は[公開後バックログ](POST_LAUNCH_BACKLOG.md)で管理し、推測で決定しません。

## 将来拡張と過剰設計の防止

将来の対象地域・情報分野の拡大を妨げないよう、情報源と表示先の分離や共通参照を行います。一方、第一版では全国対応、全市町村対応、独自検索、確定したデータモデルを超える汎用化を行いません。実際の運用で得た知識を基に段階的に再検討します。
