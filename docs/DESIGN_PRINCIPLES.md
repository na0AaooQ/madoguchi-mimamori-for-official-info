# 設計原則

## 目的と役割

> 災害時などに、熊本県内の状況を確認したい方や、地域外から支援したい方が、確認したい情報を担当する公的機関・関係団体を見つけ、その団体自身の公式発表へ速やかに到達できるよう支援する。

本サイトの役割は、公的機関・関係団体自身の公式情報への入口を案内することです。行政公式サイト、ニュースサイト、速報配信サービス、真偽判定サービス、団体の評価サービスにはなりません。

## 分かりやすさを情報量より優先する

第一版では、公開画面上のまとまりを約17、管理する情報源を30件以内、常設・補助リンクを45件以内、同時に表示する期間限定リンクを8件以内とする運用上の目安を設けます。一つのカードの主ボタンは原則1〜3件です。

網羅性よりも、目的から迷わず公式情報へ進めることと、人が丁寧に維持できることを優先します。

## 速報・転載・真偽判定を行わない

- 現在の災害、避難、火災、停電、断水、運行、道路、診療などの状況を転載しない
- 最新見出しや公式ページ本文を転載・要約しない
- 非公式情報や目撃情報を掲載しない
- 情報の真偽を判定しない
- 団体や情報の信頼度を採点・ランキング化しない
- 現在の安全性を判定しない
- 避難、受診、移動などを自動判断しない
- AIによる要約や判断を行わない

変化の速い情報を転載すると、古い内容が残り、サイト側の記述が公式発表と誤認されるおそれがあります。利用者にはリンク先の公式情報を確認してもらいます。

## 人による確認を基本とする

Web検索、クローリング、スクレイピング、RSS、外部APIなどによる自動取得は行いません。公式サイトからのリンクなどを人が確認し、公式性の根拠、対象URL、公式性確認日を記録します。

期間限定リンクも、人が現在有効であることを確認した期間だけ表示します。速報性より安全性、誤認防止、維持可能性を優先します。

## 完全無料・広告なし・ログイン不要

- すべての閲覧機能を無料で提供する
- 広告やアフィリエイトリンクを掲載しない
- 広告料、協賛、寄付によって掲載順や掲載可否を変えない
- ログインやアカウント登録を求めない
- 閲覧に個人情報入力を必要としない
- 新サイト内に利用者向け入力フォームを設けない

問い合わせのみ、任意で外部の[ポートフォリオサイトのお問い合わせページ](https://portfolio.na0aaooq.com/contact.html)を利用します。外部フォームにはポートフォリオサイト側のプライバシーポリシーが適用され、名前またはハンドルネーム、メールアドレス、問い合わせ本文などの入力が必要です。

## プライバシーと安全

利用者の個人情報を掲載情報として扱いません。行方不明者、安否不明者、被災者、負傷者、患者、救助対象者、搬送先などのセンシティブな情報を掲載しません。

ホスティング、CDN、アクセスログ、アクセス解析、Cookieは未確定です。「一切保存しない」「絶対に使用しない」などとは断定せず、実装構成の決定後に実際の構成に基づくプライバシー説明へ更新します。

## モバイル優先

- スマートフォンとタブレットを優先する
- 基本は1カラムとし、タブレット・PCでは必要に応じて2カラムとする
- 横スクロール前提の表を使用しない
- 大きなタップ領域を確保する
- 閉じたカードでも主リンクへ到達できるようにする

## アクセシビリティ

- 色やアイコンだけで状態・意味を伝えない
- 適切な見出し階層を使い、各ページの`h1`は一つにする
- キーボード操作に対応する
- 本文へ移動するスキップリンクとページ内アンカーを設ける
- JavaScriptなしでも主要リンクと詳細を利用できるようにする
- 外部リンクは原則同じタブで開く
- 外部サイトへ移動することを明示する
- PDFへのリンクはPDFであることを事前に表示する
- 「こちら」だけの曖昧なリンク文言を避ける
- ライト・ダーク双方を実装する場合は十分なコントラストを確保する
- 110番・119番を誤操作しやすい大きな発信ボタンや自動発信リンクにしない

## 情報を重複管理しない

同じ団体、URL、公式アカウント、相談先をページごとに別データとして管理しません。一つの情報源を複数の分野・カードから共通参照できる構造を目指します。

例えば、#7119を消防・救急と医療から、熊本県公式の義援金を熊本県と支援・復旧から参照します。管理単位と参照関係は[データモデル](DATA_MODEL.md)に従います。具体的なJSONファイルとJSON Schemaは後続工程で実装します。

## 技術方針

### 確定している方針

- 静的HTML・CSS中心を想定する
- JavaScriptへの依存を最小限にする
- JavaScriptなしでも主要リンクを利用可能にする
- AI、外部API、自動取得を使用しない
- 新サイト内に入力フォームを作らない
- 第一版から日本語・英語へ対応し、日本語を標準言語とする
- 管理データの正本にJSONを使用する
- 言語共通のcoreと日英localeを分離する
- JSON Schema検証とファイル間の意味検証を分離する
- Errorがある場合は公開成果物を生成しない
- 内部確認履歴と内部項目を公開成果物へ含めない

### 未確定事項

- ホスティング方式、AWS構成、ドメイン
- URLパス構成と英語版を`/en/`へ配置するか
- CI/CD
- JavaScriptを使用する具体的範囲
- アクセス解析、CDN・サーバーログ、Cookie
- ライト・ダークモードの具体的実装
- 全国展開
- テストランナー、Linter、Formatter、検証ライブラリ

未確定事項は実装前または構成決定時に検討し、推測で決定しません。

## 将来拡張と過剰設計の防止

将来の対象地域・情報分野の拡大を妨げないよう、情報源と表示先の分離や共通参照を行います。一方、第一版では全国対応、全市町村対応、独自検索、確定したデータモデルを超える汎用化を行いません。実際の運用で得た知識を基に段階的に再検討します。
